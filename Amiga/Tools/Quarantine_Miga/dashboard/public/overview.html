Miga Overview

This page explains the core idea behind the project: it does not try to emit perfect Amiga code in one pass. It uses a verified feedback loop to iteratively build and improve working assembly.

Return Home

1. Core Idea

The project is designed to generate working Amiga code through an autonomous, metric-driven evolutionary process. It does not "hallucinate" a finished program from scratch in one pass. Instead, it provides the infrastructure for an agent or mutation loop to make small changes, evaluate them, and keep only the changes that improve the measured result.

2. How It Generates Code

  1. Iterative optimization (program.amiga.md): an agent or script starts from an initial seed such as amiga_workspace/main.s, modifies the code, assembles it with vasm, runs it in vAmigaWeb, and keeps the change only if the score improves.
  2. Autonomous mutation loop (amiga_copper_mutation_loop.py): the loop can work in heuristic mode with hardcoded Copper-list repair rules, or in LLM mode where OpenAI or LM Studio chooses among valid mutation candidates.
  3. Corpus-driven development: the project ships with a curated amiga_workspace/corpus/ pool. Scripts like build_runnable_manifest.py reduce that pool to sources that are already known to assemble and run cleanly, giving the system safer starting points.

3. Mutation Modes

  • Heuristic mode: uses built-in structural rules to densify degraded Copper lists toward a known-good reference. It can fill gaps, shift pairs, and remove redundant instructions.
  • LLM mode: sends a pool of valid mutation candidates to an LLM and asks it to choose the most promising next step based on structure and recent outcomes.

4. Performance Verification

The "working" part is enforced by a multi-stage validation pipeline.

  • Assembly: vasm confirms the 68000 assembly is syntactically valid.
  • CPU verification: vamos provides deterministic instruction-level validation where applicable.
  • Visual validation: benchmark evaluators compare emulator screenshots against golden reference images to confirm the intended visual result.

5. What The Project Provides

In practice, the repo provides the machinery for an AI or scripted loop to write, test, score, and preserve Amiga code improvements. That is what allows the system to move from a simple baseline toward more complex and higher-performing assembly through many small verified iterations.
