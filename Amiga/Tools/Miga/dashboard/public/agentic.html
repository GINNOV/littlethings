Miga Agentic Guide

The README already says to point a coding agent at program.md. This page shows what that looks like in practice with local CLI agents, and how to switch between the ML loop and the Amiga loop. Return to the live dashboard

1. Pick The Right Protocol File

  • program.md: use this for the original MLX training loop around train.py and val_bpb.
  • program.amiga.md: use this for the Amiga evaluator loop around amiga_workspace/main.s and score.
  • Tell the agent to read README.md first, then the matching program file, then follow that file as the operating procedure.

2. Codex Interactive Example

The local codex CLI is installed on this machine. From the repo root, start an interactive session with the exact protocol file you want it to follow.

Amiga loop example:

cd /path/to/Miga
codex "Read README.md and program.amiga.md. Use program.amiga.md as the operating procedure. Start with the Setup checklist, run one baseline evaluation, report score/assembled/emulator_ok/verify_ok, then stop and propose the next edit."

ML loop example:

cd /path/to/Miga
codex "Read README.md and program.md. Use program.md as the operating procedure. Inspect git state, run one baseline training experiment, report val_bpb, then stop and propose the next experiment."

If you want Codex to open directly in this repo, the equivalent form is codex -C /path/to/Miga "...".

3. Gemini CLI Interactive Example

The local Gemini CLI is also installed as gemini. Its -i flag runs the initial prompt and stays interactive.

Amiga loop example:

cd /path/to/Miga
gemini -i "Read README.md and program.amiga.md. Use program.amiga.md as the operating procedure. Start with the Setup checklist, run one baseline evaluation, report score/assembled/emulator_ok/verify_ok, then stop and propose the next edit."

ML loop example:

cd /path/to/Miga
gemini -i "Read README.md and program.md. Use program.md as the operating procedure. Inspect git state, run one baseline training experiment, report val_bpb, then stop and propose the next experiment."

4. What Happens After You Run It

The examples above are not just "open the repo and think about it" prompts. They tell the agent to execute one concrete baseline pass, report the result, and stop before the open-ended mutation loop begins.

For the Amiga example, the agent should:

  1. Read README.md and program.amiga.md.
  2. Inspect the current branch and repo state.
  3. Check the setup items in the Amiga protocol, including the evaluator commands and browser backend dependencies.
  4. Run one evaluator baseline, typically through python amiga_eval.py > run.log 2>&1.
  5. Extract and report score, assembled, emulator_ok, and verify_ok.
  6. Stop and propose the next edit instead of immediately changing amiga_workspace/main.s.

For the ML example, the agent should:

  1. Read README.md and program.md.
  2. Inspect the current branch, commit, and local experiment state.
  3. Run one baseline training pass, typically through uv run train.py > run.log 2>&1.
  4. Extract and report the current val_bpb result.
  5. Stop and propose the next experiment instead of jumping straight into repeated edits of train.py.

The CLI changes who is driving the terminal, but the prompt content controls the behavior. With the examples on this page, both Codex and Gemini should do a baseline-first pass, summarize what happened, and wait for the next move.

5. Prompt Shape That Works

Good agent prompts in this repo are explicit about four things:

  1. Which protocol file is authoritative.
  2. Which loop you want: ML or Amiga.
  3. What the first stopping point is.
  4. What files are off-limits.

Template:

Read README.md and <program file>.
Use <program file> as the operating procedure.
Do not modify unrelated repo files.
First do: <baseline / inspection step>.
Stop after: <score summary / proposed next edit>.

6. Good First Agent Tasks

  • Run the baseline once and summarize the current score or val_bpb.
  • Inspect the current git state before any mutation or experiment.
  • Compare the latest kept run against the current candidate before editing.
  • Propose one small next change instead of asking for a whole strategy rewrite.

7. Common Failure Modes

  • Using program.md when you actually meant the Amiga workflow in program.amiga.md.
  • Letting the agent edit the evaluator harness when the protocol says to focus on the mutable target file.
  • Skipping the baseline run, which makes keep-or-revert decisions ambiguous.
  • Giving the agent no stop condition, which often turns one safe experiment into uncontrolled repo-wide edits.
