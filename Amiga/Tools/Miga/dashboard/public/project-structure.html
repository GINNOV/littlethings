Miga Project Structure

This page maps the repository at a high level so it is easier to tell which files are source, which files are runtime outputs, and where each dashboard feature connects back into the project. Return to the dashboard guide or the live dashboard .

1. Top-Level Layout

The repository still contains the older MLX training scaffold, but the active browser dashboard and Amiga workflow live alongside it at the root.

If you are working on the Amiga run loop or dashboard, start with dashboard/, amiga_workspace/, and the top-level amiga_eval*.py scripts.

2. Dashboard Files

  • dashboard/server.js: Express server, API routes, queue management, run execution, and archive serving.
  • dashboard/public/index.html: the monitor UI shell.
  • dashboard/public/app.js: browser-side polling, rendering, charts, and form behavior.
  • dashboard/public/settings.html: project-level saved defaults for dashboard and terminal tools.
  • dashboard/public/settings-guide.html: documentation for what each setting means and when to use it.
  • dashboard/public/how-to.html: the operator walkthrough for using the dashboard.
  • dashboard/public/project-structure.html: this repository-map page.
  • dashboard/public/agentic.html: practical agent-run examples for the repo protocols.
  • dashboard/public/credits.html: project credits, dependency pointers, and asset provenance notes.
  • dashboard/VERSION: footer version shown by the UI and guide pages.

3. Workspace Tree

The amiga_workspace/ tree holds editable source, benchmark fixtures, corpus material, and packaging helpers. 

amiga_workspace/
|- main.s
|- startup-sequence
|- presets/
|- adf/
|- benchmarks/copper_bars/
\- corpus/
  • amiga_workspace/main.s: the default editable source seed for normal validation runs.
  • amiga_workspace/benchmarks/copper_bars/: fixed benchmark assets, golden image, source-built mutation target, and disk files.
  • amiga_workspace/corpus/: candidate source pool plus manifests and helper scripts for selection.
  • amiga_workspace/adf/: template disk area for packaging runs.
  • amiga_workspace/presets/: known success or failure source presets for controlled tests.

4. Evaluators And Run Modes

  • amiga_eval.py: normal assemble, emulate, and verify evaluator.
  • amiga_eval_benchmark.py: fixed known-good Copper reference benchmark.
  • amiga_eval_benchmark_source.py: source-built Copper mutation benchmark.
  • amiga_eval.toml: command and scoring configuration shared by the Amiga evaluators.
  • program.amiga.md: agent protocol for the keep-or-revert loop.

5. Runtime Outputs

Runtime artifacts are intentionally kept outside the source folders so they are easy to inspect and easy to discard.

  • build/amiga/: latest generated reports, logs, screenshots, captures, and selection metadata.
  • build/amiga/runs/: archived per-run folders exposed in the dashboard as recent runs.
  • results_amiga.tsv: append-only score history shown in the History table and trend chart.

If the dashboard displays the latest report or a recent archived run, it is reading from these generated locations.

The workspace folder was renamed to amiga_workspace/, but the generated-output directory intentionally remains build/amiga/.

6. ROMs And External Inputs

  • roms/: Kickstart ROM files the dashboard enumerates for the ROM picker.
  • README.md: run commands and a high-level explanation of the mixed MLX plus Amiga layout.
  • explainer.md: plain-language terminal walkthrough for the Amiga flow outside the browser UI.

7. Common Edit Targets

  1. If you want to change dashboard layout or copy, edit dashboard/public/index.html.
  2. If you want to change dashboard behavior, API polling, or charts, edit dashboard/public/app.js.
  3. If you want to change queueing, archive handling, or server routes, edit dashboard/server.js.
  4. If you want to change the default validation source, edit amiga_workspace/main.s.
  5. If you want to change benchmark fixtures or the Copper mutation task, work under amiga_workspace/benchmarks/copper_bars/.
  6. If you want to change source selection or corpus filtering, work under amiga_workspace/corpus/ and its scripts.

8. Mental Model

The dashboard is only the operator surface. The actual run pipeline is: queue a job in the browser, execute it in dashboard/server.js, call one of the top-level evaluator scripts, read and write generated files under build/amiga/, then render the latest state and history back into the browser.
