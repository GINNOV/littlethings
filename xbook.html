What it does

Bookmark on the go. Later, run one Process inbox pass to import, enrich, and index—so you can find ideas by meaning, not by scrolling platform UIs.

Unified inbox

Delta-sync X bookmarks and YouTube playlists into one library. Folder membership stays in sync without re-burning tweet API reads on known items.

Local AI enrichment

Summaries, categories, and tags via your models. Chat can run on a remote vLLM host while embeddings stay on Ollama—split base URLs are first-class.

Semantic search & Ask AI

Vector embeddings power concept search and chat-style answers with citations from your library—not generic web RAG.

Agent API

Local HTTP API for tools like Hermes: search bookmarks, pull context, draft into Obsidian—credentials and data never leave your machine.

Day-to-day flow

First launch points you at Settings and Docs when the library is empty; Process inbox stays soft-disabled until OAuth and a chat model are ready.

  1. 01

    Connect

    X and optional YouTube OAuth under Settings → Connections.

  2. 02

    Configure AI

    Chat model + embedding model (and separate embed host if needed). Test LLM.

  3. 03

    Process inbox

    One button: sync → enrich pending → index embeddings for the active tab.

  4. 04

    Retrieve

    Filter the library, semantic search, or call the Agent API from your writing stack.

Built for operators

Cost-aware X sync

Monthly caps, live/local usage, and delta sync that does not re-fetch immutable tweets already in the library.

Index health

Dashboard shows indexed vs missing embeddings; config mistakes fail fast instead of “100 failed” noise.

Processing audit

Runs, events, and LLM request logs so you can see what enriched, what failed, and why.

Desktop or CLI

Tauri app with auto migrations and updater, or Next.js + Prisma for development and custom builds.

In-app docs

Getting started: Connections, LLM, Process inbox, Library, and Agent API—without leaving the console.

Privacy by default

SQLite, tokens, and embeddings stay on disk. You choose which LLM endpoints ever see content.
